# Book Detail presentation and task ownership

F11a implements the Book Detail composition in `screens/BookDetail.tsx`, `components/book-detail/BookReadingHeader.tsx` and its feature stylesheet. [Checkpoint31](frontend-renewal/31-book-detail.md) owns verification and remaining scope.

The first content region contains the cover, complete title/author, one current-page summary, and Start/Pause/Resume reading plus Log progress. Unknown total pages has no invented percentage. These controls precede every content tab in DOM order. Five existing content groups remain: Overview, Progress, Reviews, Journal and Logs. Progress retains correction and derived statistics; journal/review children retain their established task owners. Correction is still explicitly different from logging activity. ProgressLogger accepts an optional connected return-focus ref; Book Detail supplies its stable Log progress invoker. Its other consumer, Dashboard, retains default behavior.

Phone and tablet use one column; a split appears only when the **actual content container** reaches 60rem. A sidebar or larger root font can prevent this split. At very narrow content widths the identity stacks, avoiding a narrow title strip. Tabs wrap into additional rows instead of hiding the last groups beyond an invisible rail. Radix provides panel relationships and keyboard navigation without the shared capsule styling. The page has no added swipe recognizer, scroll container, fixed action footer or animated entrance. Native/browser navigation remains owned by MobileLayout and the Back coordinator.

More is a visible, labelled inline disclosure containing Add to list, Share, Edit and separated Delete. The membership owner stays mounted through resizing. Delete uses the existing LibraryRemoveDialog pending/refusal/error/retry behavior and returns focus to its invoker. A successful delete follows the existing Library destination. Failure remains in the task; a response after Book Detail unmount/account/identity change cannot redirect the replacement screen.

Mark finished still calls `bookOperations.update`, with the existing completed/current-page/date semantics. Its new confirmation explicitly explains that this does not log a session or stop a timer. A synchronous lock covers confirmation and the write; pending disables another update, failure is retained inline, and success reports the local-device boundary. An older in-flight detail refresh cannot overwrite that confirmed update. This is **not** a new domain transaction, reward event or remote-sync acknowledgement.

Same-book visible timer: running shows Pause reading and paused shows Resume reading, dispatching the corresponding existing TimerContext method. Another book or no visible timer uses `startTimer`; TimerContext retains the replacement decision, permission request, time calculation and persistence. This page does not start a second session for its own active book. Provider-level reentry, recovery, Finish and native lifecycle acceptance remain F11c.

BookDetail and its matching skeleton use the same feature geometry; BookListDetail's separate skeleton remains intact. Existing themes, Iconoir, Inter/Merriweather/Playfair and cover assets remain. Primary action text uses foreground/background tokens for contrast; the primary brand token supplies its inset accent and progress indicator. OS reduced-motion behavior needs no new animation exception.

F11b must address the full ProgressLogger/ProgressTracking/QuickProgressWidget experience and persistence failure boundaries. F11a tests opening and resize retention of these existing children; it does not certify logger upload, pending dismissal, correction validation, once-only activity or offline database durability. EditBook, full journal/review renewal, physical native/AT checks and global scroll restoration retain their separate owners.
