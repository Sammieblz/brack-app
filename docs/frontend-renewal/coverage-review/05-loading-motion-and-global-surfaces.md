# Loading, motion and global surfaces: coverage reconciliation

Source review at `db076cf`, 2026-09-28. No new browser/device/performance result is claimed. This extends the route/consumer reviews; it does not replace the existing motion specification or established domain contracts.

## What the original implementation sequence failed to establish

The original [06 motion/loading plan](../06-motion-gestures-performance.md) required caller-aware loading, preserved chrome for lazy routes, interrupted/reduced motion, task-specific feedback and measured navigation performance. F04 fixed selected immediate-save/haptic behavior; it did not close those whole-app requirements. F00 has no completed route-performance baseline in the ledger. Deferring visual refinement to F19 is reasonable; deferring the investigation of the user's reported navigation lag until after changing the global shell is not adequate evidence for that shell.

Graphify query `BrandLoader LoadingSpinner AppLoadingScreen PageTransition CelebrationOverlay InkGainAnimation useReducedMotion` returned actual owners including `PageTransition`, `LogoSpinner`, badge/streak overlays and `useReducedMotion`; several query terms were merely search vocabulary, not actual component names. The returned neighborhood was truncated. Obsidian `App.tsx.md` and `PageTransition.tsx.md` links were checked against source. There is no `BrandLoader.tsx` file/note: the implementation is **BrackLoader exported from LogoSpinner.tsx**. The census prevents invented names and distinguishes the unused `LoadingSpinner` adapter from live loading callers.

The source census currently finds no application import path to `BookCard`, `ReviewComments`, `QuoteCollection`, `StreakDisplay`, `StreakCalendar`, `StreakHistoryTimeline`, `StreakFlame`, `SuccessCheckmark`, `LoadingSpinner` and several `mobile/*` alternatives.
