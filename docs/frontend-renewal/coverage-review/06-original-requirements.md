## Twenty-principle execution trace

These are the same selected principles in [08](../08-ux-laws.md), not a new or legally binding list. Listed current examples demonstrate direction, not whole-app acceptance. The root problem was missing application evidence, not too few UX-law descriptions.

| Principle | Current relevant evidence | Next concrete application / acceptance |
| --- | --- | --- |
| Aesthetic–Usability Effect | Source preserves BRACK identity; few actual-screen captures | Actual-font phone/tablet comparisons; recognize primary action independently of visual preference |

| Fitts's Law | Adaptive close/tab targets improved | Actual medium Library actions, time/media controls and touch error/target measurements |
| Goal-Gradient Effect | Existing progress/goal/reward domain state | F11/F13/F17 truthful remaining amounts, pending/local/confirmed distinction |

| Proximity | Some associated field help/errors | CR01 all live composers; CR03/07 reflow keeps hints/actions with their task |

## Official sources revisited

The linked sources inform decisions. They do not prove installed integration, native behavior, conformance or actual product coverage. Retrieval here supplements [12 research decisions](../12-research-decisions.md); it does not change installed dependencies.

- [Ionic components](https://ionicframework.com/docs/components), retrieved 2026-09-28, rendered v9 catalogue. Action sheets, content, date/time, menus/split panes, lists/reorder and navigation are relevant candidates/patterns. F06's specific tested routing/modal failure remains the adoption boundary; a catalogue alone proves no integration.
- [Ionic native APIs](https://ionicframework.com/docs/native), retrieved 2026-09-28. Capacitor is the native capability layer. Inspect actual installed camera, haptic, keyboard, splash and other adapters per task instead of assuming every documented plugin exists in BRACK.
- [Samsung One UI guide](https://design.samsung.com/global/contents/one-ui/download/oneui_design_guide_eng.pdf), retrieved as a93-page PDF. Reviewed text on printed p7 (viewing/reachable interaction areas), p12 (responsive device/window composition), pp30–32 (action bar versus destinations and tablet navigation). Apply reachability, task grouping and coherent adaptive behavior; do not copy Samsung branding, dated dimensions or all recommendations mechanically.
- [Apple swipe article](https://developer.apple.com/documentation/uikit/handling-swipe-gestures) and [Apple HIG gestures](https://developer.apple.com/design/human-interface-guidelines/gestures) remained JavaScript/retrieval-limited here. **Do not claim a full article read or derive React recognizer code from unavailable UIKit prose.**
- [Material gestures](https://m3.material.io/foundations/interaction/gestures) again yielded a JavaScript shell. [Android's official gesture-navigation guidance](https://developer.android.com/develop/ui/views/touch-and-input/gestures/gesturenav) was readable: system-edge conflicts require explicit treatment; lower home/quick-switch gestures cannot simply be appropriated by the application. This reinforces testing actual live handler conflicts.
- [Laws of UX](https://lawsofux.com/) catalogue was retrievable; it contains more than twenty entries. The existing twenty selected principles and task-level acceptance remain the traceable scope.
- [W3C focus-not-obscured explanation](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) supports checking author chrome against keyboard focus. Broader WCAG, real AT and legal applicability remain the separate technical/release work in07/10, not implied by one criterion or this review.

No new external visual asset, icon/font substitution, native dependency or legal-policy text was added.
