# Twenty UX principles applied to BRACK

Reviewed 2026-09-27. The requested [Laws of UX site](https://lawsofux.com/) now lists more than twenty entries. This plan selects twenty relevant principles; it does not claim they are a statutory standard or a universally fixed list. The source summaries below are brief paraphrases. The proposed BRACK decisions and tests are this audit's application of them.

Use these as design hypotheses. They do not override accessibility, honest feedback, domain correctness, or observed reader behavior. In particular, no arbitrary seven-item limit, invented 80/20 usage statistic, fake progress, artificial waiting time, or coercive streak design follows from these principles.

| # / source | Useful idea | Proposed BRACK application | Observable acceptance / misuse to avoid |
| --- | --- | --- | --- |
| 1. [Aesthetic–Usability Effect](https://lawsofux.com/aesthetic-usability-effect/) | Appearance influences perceived ease. | Retain the distinctive type, theme and logo system; align spacing and quiet passive surfaces before adding decoration. | Readers can identify the next action without explanation. Measure completion separately from visual preference; beautiful errors still fail. |
| 2. [Doherty Threshold](https://lawsofux.com/doherty-threshold/) | Prompt response supports continuous interaction. | Render the shell/cached content promptly; acknowledge taps immediately; localize pending feedback. | No fixed delay before opening a saved book. Measure timings in 06/10; do not pretend every network task finishes within a universal threshold. |
| 3. [Fitts's Law](https://lawsofux.com/fittss-law/) | Reach and target dimensions affect acquisition. | Reachable Start/Log controls, generous calendar cells, separated destructive options and touch-sized menu triggers. | Measure hit boxes and one-handed errors at compact widths; keep the existing small icon drawing inside a larger target. |
| 4. [Goal-Gradient Effect](https://lawsofux.com/goal-gradient-effect/) | Visible proximity can motivate completion. | Clearly show real reading progress and remaining goal amounts, including audio/percentage semantics where supported. | Numbers reconcile with domain state. No fabricated starting progress, guilt copy or reward claim before confirmation. |
| 5. [Hick's Law](https://lawsofux.com/hicks-law/) | Choice complexity affects decisions. | One primary action per local context; a Library controls surface for advanced filters; grouped Settings navigation. | Users locate common actions and can discover advanced ones. Removing important controls merely to reduce a count fails. |
| 6. [Jakob's Law](https://lawsofux.com/jakobs-law/) | Familiar patterns reduce learning. | Browser links/history, native Back, labeled tabs, recognizable sheets and normal form semantics. | Browser/system/visible Back have coherent outcomes. Keep brand distinct through content and tokens rather than unexpected gesture grammar. |
| 7. [Common Region](https://lawsofux.com/law-of-common-region/) | Boundaries communicate grouping. | Group a reading action with its book; group related settings into one surface. | One logical region has a clear heading/relationship. Avoid a shadowed card around every sublabel. |
| 8. [Proximity](https://lawsofux.com/law-of-proximity/) | Distance communicates relationship. | Keep field hints/errors next to inputs, progress next to the book, and actions close to affected content. | At 200% text and in split panes, relationships remain clear in both visual and DOM order. |
| 9. [Prägnanz](https://lawsofux.com/law-of-pr%C3%A4gnanz/) | Simple visual organization is easier to interpret. | Reduce competing nav blur layers, badge shells, nested borders and decorative icon boxes. | A first scan reveals title, content, action and state. Theme identities remain; this is not a mandate to erase personality. |
| 10. [Similarity](https://lawsofux.com/law-of-similarity/) | Repeated treatment suggests repeated meaning. | Consistent selected, pending, error and destructive treatments across themes and screen families. | Same semantic action uses the semantic icon registry and same treatment. Static content does not mimic a button. |
| 11. [Uniform Connectedness](https://lawsofux.com/law-of-uniform-connectedness/) | Visible connection signals relation. | Connect selected reading period to its chart and metric; make pane selection/detail relationships visible. | A reader can state which book/period a detail belongs to. Don't add decorative connector lines everywhere. |
| 12. [Miller's Law](https://lawsofux.com/millers-law/) | Working memory is limited and variable. | Chunk Settings by task; show a remembered filter summary; keep steps/drafts visible without requiring recall. | Reader can resume a task without remembering hidden choices. Do not prescribe seven tabs or seven form fields. |
| 13. [Occam's Razor](https://lawsofux.com/occams-razor/) | Prefer sufficient simpler explanations/solutions. | One canonical runtime resolver, one gesture owner, one date value contract, existing service reuse. | Remove duplicate owners with regression evidence. Fewer files is not automatically simpler if boundaries become unclear. |
| 14. [Pareto Principle](https://lawsofux.com/pareto-principle/) | A subset of causes often dominates outcomes. | Implement the reading loop and shell before optional decorative refinements, following existing must-win surfaces. | Validate with actual task studies/telemetry when available. Do not assert an unmeasured 80% of users perform any particular task. |
| 15. [Peak–End Rule](https://lawsofux.com/peak-end-rule/) | Salient and final moments shape recollection. | Make session completion clear and reassuring; show a quiet confirmed reward; give meaningful next action or Done. | Save is trustworthy and success never blocks leaving. A celebration cannot repair lost data or disguise errors. |
| 16. [Postel's Law](https://lawsofux.com/postels-law/) | Flexible input and predictable output help interoperability. | Tolerate harmless whitespace and supported ISBN/date formats through existing parsers; present consistent dates and errors. | Ambiguous/invalid input asks for correction. Never weaken validation, privacy, or security under this principle. |
| 17. [Serial Position Effect](https://lawsofux.com/serial-position-effect/) | Position affects recall. | Keep stable navigation order and predictable Save/Cancel placement; put primary reading actions early in DOM order. | Repeated tasks retain action locations across related screens. Don't move destinations based on session engagement. |
| 18. [Tesler's Law](https://lawsofux.com/teslers-law/) | Some complexity must be managed rather than removed. | Let services own duplicate/sync rules while UI explains actionable pending/conflict states; progressively disclose advanced metadata. | Reader can recover from sync failure without seeing implementation terminology. Hidden complexity cannot mean hidden data loss. |
| 19. [Von Restorff Effect](https://lawsofux.com/von-restorff-effect/) | Distinctive items attract attention. | Reserve filled emphasis for the local primary action; use clear but restrained status accents. | Passive badges, icons and minor actions do not all compete. Color differences always have noncolor meaning. |
| 20. [Zeigarnik Effect](https://lawsofux.com/zeigarnik-effect/) | Incomplete tasks can remain salient. | Preserve writing drafts, resumable onboarding and an active-session affordance with explicit dismiss/finish behavior. | Resume restores the correct account/book/draft. Avoid nagging, artificial urgency and loss-aversion pressure. |

## Application procedure

For each screen ticket, select the two or three principles that explain a real decision. Record the before/after behavior and acceptance test. Do not add all twenty as ceremonial checkboxes to every component review. If a principle suggests hiding a feature, run a findability check and preserve an explicit entry point. If two principles conflict, prioritize task completion and accessibility and record why.

For example, Library simplification uses Hick, Proximity and Fitts: combine redundant status choices, group filter controls, retain a labeled touch-sized control. It does not remove useful counts or turn filtering into an undocumented gesture. Reading completion uses Peak–End and Doherty: immediate saved state and a restrained optional moment, with no timer delaying navigation.
